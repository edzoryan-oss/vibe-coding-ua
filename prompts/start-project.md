# Стартовий промпт для AI-проєкту

Скопіюй текст нижче, заміни поля в квадратних дужках і додай заповнений [опис проєкту](../templates/project-brief.md). Промпт не прив'язаний до конкретної моделі: його можна адаптувати для ChatGPT, Codex, Claude або Gemini.

```text
Ти допомагаєш мені створити [тип продукту] для [аудиторія].

Очікуваний результат користувача:
[головна дія або користь]

Контекст і вимоги:
[встав сюди заповнений project brief]

Правила роботи:
1. Спочатку коротко повтори задачу своїми словами.
2. Назви припущення, суперечності та інформацію, без якої небезпечно починати.
3. Запропонуй план із малих етапів. Для кожного вкажи конкретний результат
   і спосіб перевірки.
4. Не починай реалізацію, доки я не підтверджу план.
5. Не змінюй файли або функції поза поточним етапом без пояснення.
6. Не вигадуй API, можливості бібліотек, результати тестів або джерела.
7. Не вставляй секрети в код. Для них використовуй змінні середовища та
   безпечний файл .env.example з порожніми значеннями.
8. Якщо зміна впливає на безпеку, дані, оплату чи доступи — зупинися,
   поясни ризик простою мовою та запропонуй безпечний варіант.
9. Після кожного етапу дай:
   - перелік змінених файлів;
   - що вже працює;
   - як це перевірити;
   - що залишається зробити;
   - відомі обмеження.

Критерії готовності:
[3–7 перевірюваних пунктів]

Почни лише з аналізу вимог і плану.
```

## Як продовжити після плану

```text
Підтверджую етап 1. Виконай тільки його. Перед змінами перевір поточний стан.
Після виконання запусти доречні перевірки й покажи фактичний результат.
```

## Як попросити виправлення

```text
Очікував: [очікувана поведінка].
Отримав: [фактична поведінка].
Як відтворити: [кроки].
Текст помилки: [повний текст без секретів].

Спочатку визнач найімовірнішу причину. Запропонуй найменшу зміну,
яка виправляє проблему, і спосіб перевірити, що не зламалося інше.
```

Не передавай моделі приватні ключі чи реальні дані користувачів навіть «для тесту».
