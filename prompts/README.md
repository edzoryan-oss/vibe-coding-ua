# Як писати промпти для створення продукту

Сильний промпт — це не довга магічна фраза. Це коротка специфікація, у якій AI розуміє контекст, потрібний результат, обмеження та спосіб перевірки.

## Мінімальна структура

```text
Контекст: хто я і для кого створюю продукт.
Результат: що саме має працювати після виконання.
Обмеження: технології, бюджет, термін, дані, яких не можна торкатися.
Критерії готовності: як ми перевіримо результат.
Формат відповіді: план, код, таблиця, список змін тощо.
```

## Приклад слабкого й сильнішого запиту

Слабкий:

```text
Зроби сайт для кав'ярні.
```

Сильніший:

```text
Створи односторінковий сайт українською для невеликої кав'ярні у Львові.
Головна дія — відкрити маршрут у Google Maps. Потрібні: меню з цінами,
години роботи, адреса й кнопка Instagram. Сайт має коректно працювати
на екрані 360 px, бути доступним з клавіатури й не використовувати
платні сервіси. Спочатку запропонуй структуру сторінки. Код пиши лише
після мого підтвердження. Наприкінці дай короткий чекліст перевірки.
```

## Робочий цикл

1. Попроси AI повторити задачу своїми словами й назвати припущення.
2. Узгодь короткий план із результатом кожного етапу.
3. Виконуй один етап за раз.
4. Після кожного етапу проси описати змінені файли та спосіб перевірки.
5. Якщо щось зламалося, передай точний текст помилки й умови відтворення.

Для нового проєкту використовуй [стартовий промпт](start-project.md) разом із [шаблоном опису](../templates/project-brief.md).

## Чого не варто робити

- не вставляй у чат реальні ключі, паролі, персональні або клієнтські дані;
- не проси переписати весь проєкт, якщо потрібне локальне виправлення;
- не приймай твердження «все працює» без команди, тесту або ручної перевірки;
- не змішуй у одному запиті дизайн, архітектуру, міграцію даних і запуск;
- не змушуй модель вигадувати джерела — надавай посилання або проси чітко позначати невпевненість.
