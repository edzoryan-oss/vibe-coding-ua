# Як не віддати AI свої ключі й паролі

API-ключ, токен доступу, пароль бази даних і приватний ключ — це секрети. Їх не можна вставляти у промпти, браузерний JavaScript, публічний репозиторій, Issue, лог або скриншот.

## Безпечна базова схема

1. Зберігай локальні секрети у `.env`, а в хостингу — у розділі Environment Variables або Secrets.
2. Додай `.env` та його варіанти до `.gitignore`.
3. У репозиторії залишай тільки `.env.example` з назвами змінних і порожніми значеннями.
4. Читай приватний ключ лише в серверній частині застосунку.
5. Надавай ключу мінімальні права й окремий ключ для кожного середовища.

Приклад без реального секрету:

```dotenv
OPENAI_API_KEY=
DATABASE_URL=
```

Серверний код може читати `process.env.OPENAI_API_KEY`. Код, який завантажується в браузер, не повинен отримувати приватний ключ. Назви на кшталт `PUBLIC_`, `NEXT_PUBLIC_` або `VITE_` часто означають, що значення потрапить у клієнтський пакет — перевіряй правила свого фреймворку.

## Якщо ключ уже опубліковано

1. **Негайно відклич або перевипусти ключ** у сервісі, який його видав.
2. Перевір журнали використання, витрати й підозрілі запити.
3. Заміни секрет у всіх середовищах, де він використовувався.
4. Видали його з поточного коду та, за потреби, очисть історію Git.
5. Попередь учасників команди, що старий ключ більше не можна використовувати.

Простого видалення рядка в новому коміті недостатньо: секрет може залишитися в історії, форках, кешах і клонованих копіях. Відкликання ключа — перша дія, очищення історії — наступна.

## Корисні перевірки

- увімкни [secret scanning](https://docs.github.com/en/code-security/concepts/secret-security/secret-scanning), якщо він доступний для репозиторію;
- перед комітом переглядай `git diff --staged`;
- шукай підозрілі назви: `API_KEY`, `TOKEN`, `PASSWORD`, `PRIVATE_KEY`;
- не копіюй повні журнали помилок у публічні звернення без очищення.

Офіційна інструкція GitHub про очищення історії: [Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
